# 샌드박스네트워크 | 업무 정보 탐색과 실행 흐름 개선

> 사내 업무에서 발생하는 정보 탐색과 대기·확인 문제를 사용자 경험 관점으로 분석하고, 운영자가 설명·검토·개선에 활용할 수 있는 화면과 가이드로 구조화했습니다.

## 프로젝트 개요

샌드박스네트워크의 경영지원 Slack 봇, 사내 문서 검색, 전자계약 업무 흐름을 살펴보며 사용자가 멈추는 지점과 다음 단계에서 확인해야 할 정보를 정리했습니다. 기존 봇의 기반 시스템을 새로 개발한 역할이 아니라, 운영 데이터와 실제 업무 흐름을 분석하고 개선 요건 및 설명 자료를 만드는 역할을 맡았습니다.

| 항목 | 내용 |
| --- | --- |
| 업무 범위 | 경영지원봇 운영 개선, 문서 검색 흐름 설명, 전자계약 업무 개선 검토 |
| 나의 역할 | 운영 데이터 확인, 문제 정의, 업무 흐름 및 예외 상태 정리, 설명 화면·가이드 제작 |
| 활용 역량 | UX 관점의 정보 구조화, UI 설계, HTML/CSS/JS 퍼블리싱, AI 도구 활용 |

## 문제 → 개선 → 결과

### 01. 같은 질문의 반복 전송과 운영 지표 왜곡

**문제**  
봇의 답변을 기다리는 동안 화면에 변화가 거의 없었습니다. 같은 사용자가 25~30초 간격으로 질문을 두세 번 다시 보낸 사례가 8월 이후 17건 확인됐습니다. 관련 문서 검색 유사도가 0.84였던 질문도 반복 전송되어, 답변 품질만으로 원인을 단정하기 어려웠습니다.

**개선 · 반영 완료**  
반복된 동일 질문을 집계에서 한 건으로 계산하도록 기준을 정리하고 반영했습니다.

**확인된 결과**  
9월 7일 유사도 집계가 **46.7%에서 50.0%로 정정**됐습니다. 이는 답변 정확도 향상 수치가 아니라, 중복 전송으로 왜곡된 운영 지표를 바로잡은 결과입니다.

**추가 개선 검토**  
답변 대기 중 ‘문서를 찾는 중 → 관련 내용을 확인하는 중 → 답변을 정리하는 중’과 같은 단계별 상태 안내를 제안했습니다. 실제 적용이나 반복 질문 감소 효과는 확인된 결과로 표기하지 않습니다.

### 02. 문서 검색 과정을 이해하기 어려운 문제

**문제**  
Notion과 Google Drive 문서를 검색 대상으로 정리하고 질문의 근거를 찾는 과정은 여러 단계로 이루어져 있어, 사용자와 운영 담당자가 어디에서 기다리거나 확인해야 하는지 파악하기 어려웠습니다.

**개선 · 설명 자료 제작**  
문서가 검색 대상으로 들어오는 과정과 질문에 답하는 과정을 분리해 설명 화면과 가이드로 정리했습니다. 검색 대상, 관련 문서 확인 순서, 근거 부족·권한 문제, Slack 이벤트 중복 처리처럼 운영 시 확인할 상태와 예외를 드러냈습니다.

**확인된 결과**  
업무 흐름과 확인 지점을 설명 자료로 구조화했습니다. 검색 정확도 향상이나 응답 시간 단축은 측정된 결과로 제시하지 않습니다.

**추가 개선 검토**  
답변의 근거 문서와 원문 위치를 함께 보여주는 방향을 검토했습니다. 제품 기능의 구현 완료로 표기하지 않습니다.

### 03. 전자계약에서 자동 진행 범위를 판단하기 어려운 문제

**문제**  
수신 메일 확인, 계약 정보 대조, 담당자 공유가 이어지는 업무에서 확인되지 않은 정보까지 자동으로 다음 단계에 넘기면 판단이 필요한 지점을 놓칠 수 있습니다.

**개선 · 업무 흐름 및 요건 정리**  
수신 건 분류와 계약 정보 확인 등 단계를 나누고, 회사·계약 상대방·크리에이터·플랫폼·계약 금액의 일치 여부를 다음 단계 진행 조건으로 정리했습니다. 정보가 불일치하거나 확인이 어려운 건은 담당자가 검토하도록 하는 방향을 제시했습니다.

**확인된 결과와 범위**  
자동화 범위와 검토 조건을 문서화했습니다. 전자계약 전체 제출·날인 자동화와 담당자 공유의 자동 실행은 이 프로젝트에서 확인된 완료 성과로 주장하지 않습니다.

질문, 답변, 근거, 다음 행동을 구분하고 대기·중복·근거 부족·확인 필요 상태를 별도로 정리했습니다. 퍼블리싱 경험을 활용해 이 흐름을 설명 화면과 가이드로 옮겨, 비개발자도 업무의 현재 상태와 판단 기준을 공유할 수 있게 했습니다.
